# 全方向ロボットの矢印キー操作

## メンバー向けの起動手順（Windows）

このリポジトリには、全方向ロボットのADuC814用ファームウェアと、USB経由で操作するWindows用Pythonプログラムが含まれます。実機に書き込み済みの版は [omni_front1_v4_sensor2.ihx](firmware/omni_front1_v4_sensor2.ihx)、PC側の入口は [keyboard_drive.py](keyboard_drive.py) です。

1. このリポジトリをクローンするか、GitHubの「Code → Download ZIP」で取得して展開します。
2. Python（このプロジェクトでは3.14を使用）をインストールし、このREADMEのあるフォルダーで `python -m pip install -r requirements.txt` を実行します。
3. ロボットなしで試すには `キー操作.cmd` をダブルクリックします。
4. 実機を操作するにはUSBを接続し、本体電源OFFの状態でスイッチを **Load** に合わせ、電源を入れて `実機キー操作.cmd` を起動します。操作画面をクリックしてからキーを押します。別のPCではCOM番号が変わるため、通常は自動検出を使います。

既存機の操作は手順4で開始できます。ファームウェアを再導入する場合は、本体電源OFF → **Write** → ONの順で起動してから、実際のCOM番号を指定して `python firmware/program_aduc814.py --port COM12 --write firmware/omni_front1_v4_sensor2.ihx` を実行します。この操作は基板のプログラム領域を上書きします。完了後は電源OFF → **Load** → ONで起動します。

## ①を前にした元の基板の矢印キー操作

写真上端の白い①を前、左を②、後ろを③、右を④として操作します。USBを接続し、本体の電源を切った状態でスイッチを **Load（実行）** に合わせます。電源を入れ、デスクトップの「全方向ロボット 実機操作」を開きます。

| 操作 | 動作 |
|---|---|
| ↑・W ／ ↓・S ／ ←・A ／ →・D | 前進 ／ 後退 ／ 左移動 ／ 右移動 |
| 縦と横の移動キーを同時押し | 斜め移動。矢印とWASDの併用も可能 |
| Q ／ E | その場で左旋回 ／ 右旋回 |
| 移動キー＋QまたはE | 移動しながら旋回。W＋A＋Qなら車体の左前へ移動しながら左旋回 |
| すべて離す ／ Space | 停止 |
| Esc | 停止して終了 |

## 4つのセンサーによる進行方向の制限（実機版 v4）

デスクトップの「全方向ロボット 実機操作」から起動すると、操作画面に検知した番号と車体側の駆動状態が表示されます。基板が走行中もセンサーを読み、進行方向で検知するとその移動指令を停止します。

| 白い①の車輪を前にしたセンサー位置 | ADC入力 | 検知／解除のしきい値（12ビット値） | 制限する移動 |
|---|---|---|---|
| 1 左前 | ADC0 | 1391／1347 | 前・左・左前 |
| 2 右後ろ | ADC1 | 1391／1347 | 後ろ・右・右後ろ |
| 3 左後ろ | ADC2 | 1391／1347 | 後ろ・左・左後ろ |
| 4 右前 | ADC3 | 1391／1347 | 前・右・右前 |

現在の実機には `firmware/omni_front1_v4_sensor2.ihx` を書き込んでいます。白い紙で右後ろの2番の元の検知距離を25 cmと測り、その半分の12.5 cmで記録した値を4個に共通設定しました。実際の検知距離には各センサーの感度も影響します。`omni_keyboard` から `python firmware/build_assumed.py --half-distance firmware/half_range_20261119_170454/measurements.partial.json --reference-sensor 2` で再ビルドできます。

同時に複数が反応すると、該当する方向をすべて制限します。旋回を組み合わせた移動も、進行方向が塞がっていれば車体を停止します。障害物から離れる方向への入力と、Q／E単独のその場旋回は使えます。停止中に障害物を取り除いたときは、同じ方向のキーを一度離してから押し直すと再開します。検知距離は対象物の反射や角度で変わります。

以前の個別設定の測定記録は `firmware/sensor_measurements`、その走行用イメージは `firmware/omni_front1_v4.ihx` に保存しています。モーター停止の測定用イメージは `firmware/sensor_probe.ihx` です。

2026年11月19日にCOM12で走行用イメージを書き込み、Load側で新版の起動、4つの個別検知、物を外した後の検知解除を確認しました。確認中のUSB送信は0件で、基板から受信した駆動状態はすべて停止でした。走行中の停止距離は未測定です。

## キーの設定とファームウェアの履歴

旋回キーは英数字各1文字で変更できます。例として `python keyboard_drive.py --aduc814 --turn-keys z x` でZを左旋回、Xを右旋回に割り当てます。WASDの文字を旋回に指定した場合はその旋回割り当てが優先されます。通常の複合操作では、片方を離すと残ったキーの動きに移ります。逆方向を同時に押した場合やSpaceで停止した場合は、すべての操作キーを離してから再開します。

移動と旋回を同時に扱う版は `firmware/omni_front1_v3.ihx`（922バイト）です。2026年11月19日にCOM12のADuC814から全58ブロックの書き込みACKを確認しました。旧版は `omni_front1_v2.ihx`（70%）、`omni_front1.ihx`（45%）、`omni_assumed.ihx`（30%）として同じフォルダーに保存しています。PCは起動応答から利用可能な操作を判定します。

書き込み後、利用者がデスクトップのショートカットから起動し、実機で移動と旋回の同時操作、キー解放時の停止を確認しました。

車体にはNEC「D16805 0543W7」のICが4個あるとの報告を受けています。μPD16805のIN1とIN2に対して、H/Lを正転、L/Hを逆転、L/Lを停止として出力します。これはINCとSTBYがどちらもHの場合の動作です。基板がこの2端子を有効に保持し、ADuC814と各IN1・IN2の間は非反転で直結していると仮定しています。[μPD16805の真理値表](https://www.renesas.com/en/document/dst/upd16805-data-sheet)

PWMの上限は70%です。移動と旋回を同時に指示した場合は、各車輪の回転方向を加算し、最大が70%になるよう0%、35%、70%に配分します。通信が途絶えると設計上約250 msで停止出力に切り替わります。実トルクは未測定です。

設定変更後の再ビルドは `python firmware/build_assumed.py` です。SDCCがPATHにない場合は、引数にsdcc.exeのフルパスを指定します。実機キー操作の起動自体は既存プログラムを変更しません。書き込みツールの `--write` は既存コードを消去します。今のUSB接続のローダーは以前のセッションのプログラムのバックアップをサポートしません。[Analog Devices AN-1074](https://www.analog.com/en/resources/app-notes/an-1074.html)

## PC上で操作を試す

Windowsで「キー操作.cmd」をダブルクリックすると、画面上に真上から見た車体が表示されます。↑は前進、↓は後退、←と→は向きを変えずに横移動です。キーを押している間だけ車体が動きます。矢印を離すか、Spaceを押すか、別のウィンドウに切り替えると停止します。縦と横の同時押しで斜め移動、QとEで左右に旋回します。Escで終了します。この起動方法ではUSBポートを開きません。

シミュレーターはPC側で作った3バイトの指令を、実機用の `firmware/receiver.c` をWebAssemblyにコンパイルした受信処理に渡します。受信処理が指定した方向に画面の車体を移動します。表示速度は操作確認用の値です。実車のホイール配線、速度、慣性はモデル化していません。

## 今回の車体

2026年11月18日、CP2102（COM12）経由でADuC814の内蔵ローダーと9600 bps・8N1で双方向通信できました。電源オン時の初回記録は25バイトで先頭に乱れがありました。その後、メーカー指定の識別照会を1回送り、次の25バイトを受信しました。先頭の機種識別は `ADI 814`、全25バイトの総和の下位8ビットは0です。実測した版の4バイトは `56 32 30 20`（末尾は空白）です。[Analog Devicesのローダー仕様 AN-1074](https://www.analog.com/en/resources/app-notes/an-1074.html)

```text
41 44 49 20 38 31 34 20 20 20 56 32 30 20 0D 0A 02 28 CC 01 04 DF 00 00 4C
```

この照会で確認できたのは書き込み待機モードでの通信です。通常実行時の通信速度、走行指令、モーターへのピン割当、実機の走行・停止は未確認です。

11月18日、利用者が切替スイッチを反対側にして電源を入れ直した際も、COM12で前回と同じ起動列を受信しました。その後の識別照会にも同一の有効な25バイトが返りました。この状態で AN-1074 表14のRemote RUN（先頭アドレス0）を1回送ると、応答は `07`（NAK）のみでした。その後10秒の観測中に追加の出力はありませんでした。この時点での既存プログラムの有無や拒否の原因は未確定です。

その後、利用者はUSBを外し、電池だけで起動した後、Load側に切り替えた際に車輪が回り始めたと報告しました。USBを再接続し、あらかじめLoad側にして電源を入れた試験でも、利用者は車輪の回転を確認しました。この試験のCOM12の受信記録は9600 bps・約90秒間で0バイトでした。どの車輪がどの方向に回ったか、駆動のきっかけが既存ファームウェアかどうか、外部から走行指令を受け付けるかは特定できていません。

## 実機用の通信設定

### 既存プログラムの起動メッセージを見る

車輪をすべて浮かせ、USBを接続したまま本体の電源を切ります。通常実行時の出力を調べるには、切替スイッチをLoad（実行）側に合わせます。「起動メッセージ確認.cmd」を開き、「受信中」と出たら本体の電源を入れます。20秒間、9600 bpsで受信したバイトを表示します。USB変換器も車体電源と一緒に切れる構成では、この方法では起動時の先頭を取得できない場合があります。0バイトでも既存プログラムの有無や通信速度は判定できません。

### 新しいADuC814用受信プログラム

`firmware/aduc814.c` はUARTと約10 msのタイマー、`firmware/receiver.c` は方向指令と通信断時の停止を担当します。PC側の専用モードは `--aduc814` です。基板から専用の識別文字列を受信すると、操作の変化をすぐに送り、80 msごとに再送します。受信側では起動時・タイムアウト後に停止指令を受けてから走行指令を受理します。受信が25回のタイマー周期にわたり途絶えると停止を指示します。

モーター出力は `firmware/motors.c` に実装しました。約0.5 ms周期でPWMを更新し、20周期ごとに受信タイムアウトを更新します。uCsimで8方向の移動と左右旋回のGPIO出力、各周期での14回通電・6回空転、反転前の停止、明示停止、通信断時の停止、UART端子の保持を確認しました。

ファームウェアを書き込むときは、本体の電源を切り、スイッチを **Write（書き込み）** に合わせてから電源を入れます。書き込みには `firmware/program_aduc814.py` を使います。実機用のSDCCイメージを `--write` で指定すると、Intel HEX全体を検査してからADuC814ローダーを識別し、コード領域を消去して書き込みます。データ領域の消去・書き込み命令は送りません。ツールの通信手順は模擬ローダーで確認済みです。

写真の「D16805」が16ピンのμPD16805GSである場合、電池とUSBを外した状態で表側のIN1（6番）、IN2（7番）、INC（8番）、STBY（14番）の接続先を確認できます。途中に抵抗や別のICがあると、導通ブザーが鳴らない場合があります。[モータードライバーの端子配置](https://www.renesas.com/en/document/dst/upd16805-data-sheet)・[ADuC814データシート](https://www.analog.com/media/en/technical-documentation/data-sheets/aduc814.pdf)

### 固定コマンド式の既存ファームウェア

このプログラムは、状態が変わるたびに1件の固定バイト列を送るシリアル方式（8N1、フロー制御なし）に対応します。実機で使うには、車体のサンプルコードまたは通信仕様で、通信速度と4方向・停止の指令を確認します。定期送信や応答確認が必要な機種では送信処理の対応も必要です。USB切断時の停止は車体側のファームウェアに依存します。

その方式と一致する場合は、UTF-8のJSONに通信速度を整数の `baudrate`、5つの指令を `frames` オブジェクトの `forward`、`backward`、`left`、`right`、`stop` として指定します。値は終端文字を含む16進バイト列を表す文字列です。実機モードは起動時と終了時にも停止指令を送ります。

```powershell
python keyboard_drive.py --profile robot.json --port COM12
```

このPCにはpyserialとシミュレーター用のpywasmを導入済みです。別のWindows PCでは `python -m pip install pyserial==3.5 pywasm==2.2.3` で用意できます。同梱した `preview/receiver.wasm` はそのまま利用できます。受信コードを変更した場合は、Zig 0.14.1でこのフォルダーから再生成できます。

```powershell
zig cc -target wasm32-freestanding -Oz -nostdlib -Wl,--no-entry -Wl,--export=receiver_byte -Wl,--export=receiver_tick_10ms -Wl,--export=preview_direction -Wl,--strip-all firmware/receiver.c preview/preview_output.c -o preview/receiver.wasm
```
